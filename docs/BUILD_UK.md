# Derail-Valley-Catenary-DC — складання та перший тест

## 0. Що саме отримано

**Це вихідний проєкт 0.1.0 (foundation), а не готова DLL і не вже збудований
перегін HB–CS–CMS.** У ньому залишено тільки ядро контактної мережі, ресурси,
редактор і засоби складання. Оригінальні 31 розстановки з наданого архіву
збережено без змін як контрольну мережу. Новий прибережний маршрут задано
в `plans/` іще без координат об'єктів. Попередні FRC final.9/Rework.1 не додані
повторно: основа цього проєкту — саме останній переданий авторський ZIP.

Новий код тут не компілювався: у середовищі підготовки немає .NET SDK, твоїх
ігрових DLL, Unity Editor та Windows PowerShell. Виконано лише задокументовані
Python-перевірки даних/структури та підготовки адаптера. Спочатку потрібен
чистий smoke-test ядра, потім — тяговий тест із сумісним контролером.

## 1. Не перезаписуй робочий мод

При закритій грі скопіюй всю поточну папку

`C:\Program Files (x86)\Steam\steamapps\common\Derail Valley\Mods\Catenary-DC`

до резервної папки **поза Mods**. Також збережи робочий Git-форк і звичне
збереження гри. Новий проєкт розпакуй окремо, наприклад:

`C:\DV-Work\Derail-Valley-Catenary-DC`

У корені повинні безпосередньо бути `BUILD.cmd`, `src`, `unity_project`, `tools`,
`info.json`. Не розпаковуй поверх попереднього форка. ZIP вихідного коду не
встановлюється через Unity Mod Manager.

## 2. Програми

Використовуй ту саму **Unity 2019.4.41f2**, що й раніше. Для C# потрібен
**.NET SDK 8 або новіший**; уже встановлений тобою .NET 10 SDK підходить до
мови C# 12. Runtime-target залишається **net48** — гру не переводимо на .NET10.
Reference assemblies Framework 4.8 підтягуються через NuGet, тому наявний
Developer Pack можна залишити, але скрипт не вимагає його ручного встановлення.
Для відновлення NuGet потрібен інтернет. Unity Mod Manager залишається у грі.
Python 3.10+ потрібен лише для Python-перевірок і необов'язкового адаптера 2WE3.

## 3. Новий Unity-експорт — обов'язково один раз

У Unity Hub додай **нову** папку

`C:\DV-Work\Derail-Valley-Catenary-DC\unity_project`

і відкрий її через 2019.4.41f2. Це не старий локомотивний проєкт. Дочекайся
імпорту, перевір Console. Виконай **Catenary → Export OCS**.

Очікувані результати в `unity_project\Assets\AssetBundles`:

```text
catenary
catenary_parts
catenary.manifest
catenary_parts.manifest
catenarydc-export.json
```

Збираються лише два бандли, без моделей 2WE3. Останній JSON — запис хешів
вихідних ресурсів і результатів. Він не є розстановкою. Не копіюй сюди старі
бандли або саморобний receipt, щоб пройти перевірку.

Якщо команда не з'явилася або Unity показує червоні помилки, DLL поки не
збирай: потрібні перша помилка Console та `Editor.log`. Зміна лише C#-коду
після успішного експорту не вимагає нового експорту. Зміна моделей/CSV/сценаріїв
або їхнього складу — вимагає.

## 4. Збирання ядра

Найпростіше — подвійний клік `BUILD.cmd`. На запит встав **корінь гри**:

```text
C:\Program Files (x86)\Steam\steamapps\common\Derail Valley
```

Не `Mods` і не папку проєкту. Альтернатива в PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File 'C:\DV-Work\Derail-Valley-Catenary-DC\tools\Build.ps1' `
  -GameDirectory 'C:\Program Files (x86)\Steam\steamapps\common\Derail Valley' `
  -Configuration Release
```

Скрипт перевіряє експорт і бібліотеки гри, копіює код у робочу папку, виконує
restore/build і формує результат. **Нічого автоматично не встановлює.**

```text
artifacts\<дата-ідентифікатор>\
  work\CatenaryDC\...
  build.log
  ready-to-install\Derail-Valley-Catenary-DC\
    CatenaryDC.dll
    info.json
    catenary
    catenary_parts
    network.json
    Scenery\README.md
    build-info.json
    LICENSE_*.txt
    NOTICE.md
```

Успіх: `BUILD SUCCEEDED. Nothing was installed.` Поряд формується ZIP готового
мода. На відміну від старих збірок, файл ядра називається **CatenaryDC.dll**,
а не electric_sim.dll. Не підмінюй його і не перейменовуй під стару збірку.
За помилки збережи повний `build.log` і першу помилку, а не лише останній рядок.

## 5. Перший тест: лише контактна мережа

Повністю закрий гру. Перемісти попередній `Catenary-DC` **поза Mods**, а не в
`Mods\Catenary-DC-old`: UMM може завантажити його і звідти. Скопіюй нову папку
`ready-to-install\Derail-Valley-Catenary-DC` до `Mods`.

Для цього тесту **вимкни 2WE3CCL**, якщо не збираєш адаптер із наступного
розділу. Його пакет моделей у наданому джерелі вимагає `Catenary-DC`, а чисте
ядро свідомо має інший UMM ID `DerailValleyCatenaryDC`. CCL можна залишити
встановленим, але самі моделі без контролера не дадуть працездатної 2WE3.

Не перенось старі `scenery_fm.json`, `scenery_or.json`, `scenery.json`,
`settings.json` чи стару DLL. Почни з комплекту, створеного новим BUILD.cmd.

Завантаж окремий Sandbox на стандартній карті **без DoubleTrack**. Для огляду
підійде звичайний дизель. У Ctrl+F10 шукай **Derail Valley Catenary DC**.
У меню має бути `Network ready: ... objects`, без помилки ініціалізації.

Перевір авторські SM, FF, CP/OR та одну віддалену станцію: моделі, проводи,
переміщення/телепортацію, повторний вихід у меню та завантаження світу. У Release
не повинно бути службової стрілки підстанції. Наявність усієї колишньої авторської
мережі — очікувана: це контрольний профіль, а не наша остаточна економічна карта.

**Цей огляд не перевіряє електричну тягу.** Дизель не споживає струм із мережі.

## 6. Окремий тяговий тест 2WE3

Дивись `compat\Legacy2WE3\README_UK.md`. Там є необов'язкова команда, яка
з наданого оригінального авторського джерела збирає **окремий контролер**
`CatenaryDC.Legacy2WE3.dll`, підключений до API нового ядра. Реалізація локомотива
не повертається до основного проєкту, вихідний архів не змінюється, друга
контактна мережа не створюється. Новий адаптер тут також ще не компілювався.

Не вмикай оригінальний `electric_sim.dll` поруч із новим ядром заради пантографа:
це запускає не сумісність, а два різні моди контактної мережі. Для тягового тесту
мають працювати нове ядро + окремий адаптер + CCL/2WE3CCL.

## 7. Debug та розстановки

`BUILD_DEBUG.cmd` збирає Debug DLL. Не змішуй без потреби різні вихідні папки.
Редактор лишається в налаштуваннях UMM, керування від штатного DM1U/Microshunter.
Початково Part placement = Disabled, Eraser = false. Наявність назви DM1U в
ядрі — це підключення інструмента розстановки, не включена симуляція локомотива.

Робочі результати редактора тепер пишуться в **UserData/** у папці нового мода.
Авторські/production файли не перезаписуються. При першому читанні геометрії
користуйся Release; у Debug короткі звичайні секції навмисно відображаються
авторським `ShortWireMarker`. Live-редактор не є валідатором нових вимог.
Після зміни електричних об'єктів потрібне збереження і Reload/перезапуск світу.

Для production-сценаріїв використовується **Scenery/**. Однаковий basename
замінює бандлову розстановку; інший додає. `network.json` може обмежити перелік.
Вибір профілю має включати всі необхідні джерела живлення. Старі root-level
scenery*.json ігноруються з попередженням, щоб не підхопити legacy override.

## 8. Додаткові перевірки

```powershell
cd C:\DV-Work\Derail-Valley-Catenary-DC
python .\tools\validate_project.py
dotnet run --project .\tests\CoreLogic\CoreLogic.csproj -c Release
```

Python перевіряє структуру, CSV, сцену, метадані та статичні інваріанти коду.
C#-runner перевіряє саме підключені production-файли математики/CSV/стану
підстанції, без Unity. Він підготовлений, але **не запускався тут**. Навіть
успіх обох команд не замінює компіляцію net48 із DLL гри та проїзд.

## 9. Відкат

Закрий гру. Перемісти нове ядро і, якщо встановлено, adapter **поза Mods**.
Поверни всю попередню папку `Catenary-DC`, віднови 2WE3CCL, якщо вимикав його.
Старі ресурси й збереження будівельний скрипт не змінював. Не залишай разом
оригінальну DLL і адаптер із тим самим legacy UMM ID.
