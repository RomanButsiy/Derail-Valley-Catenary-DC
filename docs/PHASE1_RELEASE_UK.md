# HB–CS–CMS–SM: поточна прийнята мережа

Дев’ять файлів і 1867 об’єктів першого етапу збережені. Після Visual 4
застосовано прийняті зміни профілю до 6 м та піднято 161 опору з великими
рамковими консолями. Компактні кріплення останнім коригуванням не змінювалися.
Актуальний маніфест — `audit/network_6m.json`; попередній
`audit/phase1_hb_cs_cms_sm.json` залишено як історію первинного розподілу.

## Розстановки

Шлях у репозиторії: `unity_project/Assets/Catenary/Scenery/`.
Кожен новий JSON має `.meta` з постійним унікальним GUID та `assetBundleName: catenary`.

| Файл | Об’єктів | Вміст |
| --- | ---: | --- |
| `scenery_HB-CS[HB].json` | 386 | Вихід HB, нова діагональ трикутника та підхід до N09; HB1500. |
| `scenery_[HB]![CMS].json` | 33 | Знеструмлена нитка N09, її анкери та шість знаків. |
| `scenery_CS-HB[CMS].json` | 212 | Від N09 до південного підходу CS; CMS1500. |
| `scenery_CS.json` | 76 | Наскрізний маршрут CS, платформи та кріплення під переходом. |
| `scenery_CS-CMS.json` | 702 | Перегін від CS до вхідної горловини CMS; CMS1500. |
| `scenery_CMS.json` | 139 | Транзитна дуга CMS і єдина нова підстанція CMS1500. |
| `scenery_CMS-SM[CMS].json` | 94 | Вихід CMS до N04; CMS1500. |
| `scenery_[CMS]![SM].json` | 30 | Знеструмлена нитка N04, її анкери та шість знаків. |
| `scenery_SM-CMS[SM].json` | 195 | Від N04 до стику з авторською мережею біля кільця SM; SM1500. |

`[HB]`, `[CMS]`, `[SM]` позначають район живлення відповідної частини перегону;
`[A]![B]` — нейтральну нитку та її знаки, як у файлах автора. Розподіл по файлах
не створює нових анкерних стиків. Опора та використаний на ній анкер можуть
належати сусіднім файлам: вони завантажуються разом. CMS1500 визначена тільки
в `scenery_CMS.json`; HB1500 та SM1500 залишаються в авторських файлах.
Завантажувальна колія CMS не електрифікована.

## Перевірка і складання

```powershell
python tools/verify_network_release.py
python tools/validate_project.py
```

`verify_phase1_release.py` без параметрів також перевіряє поточний маніфест.
Для прямого порівняння використай прийнятий `Catenary_6m_Visual2.zip` з
`verify_network_release.py --accepted-zip`. Старий моноліт Visual 4 описує
попередню висоту і не є еталоном поточної мережі.

[Повна інструкція оновлення, вилучення тестових накладок і складання](NETWORK_6M_RELEASE_UK.md).
Після Unity-експорту повтори проїзд HB–CS–CMS–SM, звернувши увагу на стики
профілів біля тунелів, перехід і платформи CS, N09/N04 та кріплення на опорах.
