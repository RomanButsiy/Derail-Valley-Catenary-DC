# Коридор HB–GF–CME/IME · Visual 3

Прийнята після проїзду Visual 3 інтегрована у штатний бандл `catenary`.
Збережено координати, кріплення, дроти та прив’язку кожного прольоту до підстанції.
SM–HB проходить через N02, HB–GF через перенесену N08, GF–CME/IME через N07.
Західне кільце знято з електрифікації. На його кінцях залишено наскрізні ходи в бік шахт і SM–FF.

## Файли сцени

Усі JSON розташовані в `unity_project/Assets/Catenary/Scenery/`. Існуючі ресурси зберігають GUID. Кожен новий файл має власний Unity GUID і мітку бандла `catenary`.

| Ділянка | Ресурси |
| --- | --- |
| Підходи з боку SM і HB та південний трикутник | `scenery_SM-HB[SM].json`, `scenery_HB-SM[HB].json` |
| N02, N08 і N07, включно зі знаками | `scenery_[HB]![SM].json`, `scenery_[HB]![GF].json`, `scenery_[GF]![CME-IME].json` |
| Перегін HB–GF, дві сторони N08 | `scenery_HB-GF[HB].json`, `scenery_GF-HB[GF].json` |
| Підстанція GF1500 | `scenery_GF.json` |
| Підхід до шахт і стик з авторською мережею | `scenery_IME-GF[CME-IME].json`, `scenery_IME-FF[CME-IME].json` |
| Знята західна гілка | `scenery_FF-IME[FF].json`, `scenery_[FF]![CME-IME].json` містять порожні масиви, як у Visual 3. |

## Збирання та перехід з тестової версії

1. Відкрий `unity_project` у Unity **2019.4.41f2** та виконай **Catenary → Export OCS**. Запусти штатний `BUILD.cmd`.
2. Закрий гру. Якщо встановлена тестова GF Visual 1–3, перенеси **всі сім файлів** зі списку нижче з папки `Scenery` встановленого мода в резервну папку поза модом. Моноліт дублює геометрію та підстанцію GF1500. Інші шість зовнішніх файлів перекривають вбудовані розстановки з тими самими назвами.
3. Встанови нову збірку з `ready-to-install`. Штатний `network.json` з `included_scenery: null` завантажує всі райони. Якщо використовуєш власний список, включи потрібні файли з таблиці разом з їхніми джерелами живлення.
4. Після експорту оглянь підхід до тунелю з боку HB, портал із тросами біля GF та стик перед мостом біля CME/IME.

Зовнішні файли тестового пакета для видалення з активної `Scenery`:

```text
scenery_phase2_gf_visual1.json
scenery_[ff]![cme-ime].json
scenery_[hb]![sm].json
scenery_ff-ime[ff].json
scenery_hb-sm[hb].json
scenery_ime-ff[cme-ime].json
scenery_sm-hb[sm].json
```

## Перевірка

```powershell
python tools/verify_phase2_release.py --accepted-zip GF_Phase2_Visual3.zip
python tools/verify_phase1_release.py
python tools/validate_project.py
python tools/test_authoring_tools.py
```

Перша команда відтворює заміну ресурсів сімома файлами Visual 3 і порівнює всі об’єкти та їхню кратність із вбудованою мережею. Без аргументу вона перевіряє контрольні суми з `audit/phase2_gf.json`. У збірці 13 841 об’єкт у 46 файлах. Дев’ять файлів етапу HB–CS–CMS–SM перевіряються окремо.

## Наступна зйомка GF

Поточний етап охоплює перегін повз GF. У матеріалі від 5 листопада вже є геометрія 17 іменованих станційних колій у парках A–D. Для продовження потрібен проїзд саме обраним шляхом через станцію, від вхідної до вихідної стрілки. Він визначить потрібні з’єднання й дасть змогу перевірити перешкоди та місця опор уздовж цього шляху.
