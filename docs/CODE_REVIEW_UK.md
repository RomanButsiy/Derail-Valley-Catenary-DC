# Огляд вихідної основи та виконаного рефакторингу

## Джерело і межі

Основа — переданий користувачем ZIP
`Derail_Valley_electric_concept-full_circuit(1)(1).zip`, comment
`4d1a6a691415b6f08f9a76fbafdc8357485e277a`. Це не заява про поточний live HEAD
GitHub. Архів і хеші кожного його файла зафіксовані в `audit/upstream.json`.

Ціль: самостійне ядро **Derail-Valley-Catenary-DC**. Код/3D-ресурси локомотива
не входять до основного проєкту. Авторська географія не перероблена на нову
економічну карту: її залишено для порівняння поведінки старого й нового ядра.
Новий прибережний маршрут HB–CS–CMS–кільце перед SM **ще не побудований**.

## Що прибрано

З runtime вилучено `unit_A`, `unit_B`, `devices`, `circuit`, локомотивний
`car_spawn_handler`, traction/billing поля головного мода і залежні від них
utilities. Прибрано початкові тести тягового двигуна, `we6.blend`, CCL editor
бінарники, `Assets/_CCL_CARS`, кабіни/кузови/звуки та сцени локомотива.
Старі `electric_sim.sln`, абсолютні E:-посилання, `package.ps1` і updater
`repository.json` не використовуються в новому пакеті.

Збережено `catenary`, потрібні геометричні/CSV utilities, `catenary_editor`,
3D-моделі контактної мережі, матеріали, текстури, шість CSV, метадані Unity та
31 авторський scenery JSON. Це **573 файли Catenary включно з .meta**,
побайтово незмінені відносно джерела. Їхні GUID не посилаються на вилучений
локомотивний набір. Немає другої дубльованої копії JSON у C#-дереві.

## Внесені зміни коду

| Знахідка / ризик | Рішення | Межа перевірки |
|---|---|---|
| `wire.get_template()` існує тільки під DEBUG, але конструктор викликає його в Release | Метод лишено в обох конфігураціях. Release повертає CSV template; Debug зберігає **ShortWireMarker** цієї нової основи | Структура обох гілок перевірена; компіляція ще потрібна |
| Службові моделі підстанцій не мають бути видимі у Release | Явний `substation.reveal()`: Debug → base, Release → false. Електрична підстанція не видаляється | У цій основі автор уже частково ховає GantryArrow; не заявляємо, що весь механізм новий |
| У `substation.wire_voltage` доданок Z записаний як `z_offset + z_offset`, а не квадрат | Відстань винесено в `ElectricalMath.Distance`, X/Z переводяться з мм, Y залишається в м; double до віднімання/квадратів | Може змінити напругу під навантаженням; потрібен повторний тяговий тест |
| Substation містить async void / Task.Delay, які можуть пережити світ | Окремий per-world `SubstationState` оновлюється з одного FixedUpdate | 10/30 секунд тепер **ігровий час**, а не фонова затримка; пауза зупиняє countdown |
| Залежність OCS tick від всіх unit_A/B | Прибрано, замінено `CatenaryApi.SimulationStep` перед розрахунком джерел | Споживання з'являється лише від підключеного vehicle-adapter |
| Множник навантаження міг повторно потрапити до експортованого nominal maximum_load | Зберігається номінальне значення; множник застосовується тільки до runtime-state | Потрібен експортерний regression-тест у Debug |
| Помилка після створення singleton могла лишити частково завантажений світ/бандли | Власність бандлів реєструється до парсингу, startup має rollback; teardown відписує WorldMoved/Player events і очищує singleton | Статична перевірка; re-enter-world ще тестувати у грі |
| Статичні таблиці моделей переживають reload | Очищення перед кожним повторним set_up_templates | Не змінює авторські CSV |
| Жорсткий радіус пошуку контакту 60 м від origin проводу | Радіус враховує максимальну довжину завантаженого прольоту +5 м | Найдовший авторський проліт ≈80,16 м; точний контакт лишається методом автора |
| Старі assembly/type імена JSON після перейменування DLL | Allowlist-біндер семи відомих scenery-класів. Приймає legacy electric_sim без завантаження старої DLL; export пише legacy labels | Не є дозволом довільного .NET type loading |
| CSV залежить від game-private Mono.Csv | Невеликий parser для BOM, quotes, escaped quotes, CR/LF; перевірки рядків/чисел/меж | Підготовлено C# тести actual production source, тут не виконані |
| Runtime JSON змішаний зі старими overrides/експортами редактора | `Scenery/` для production overrides, `UserData/` для Debug, `network.json` для вибору | Старі root-level overrides ігноруються з попередженням |
| Порожній список tunnel_ranges індексується [0] | Додано guard | Не перепроєктовано алгоритм підземного монтажу |
| Debug distance_monitor лишався після disposal follower | Монітор видаляється, повторний Dispose безпечний | Повторний spawn/editor ще перевірити у грі |
| Нечислові settings / неприпустимі довжини / невідомі джерела | Додано guards, дубльовані source IDs не допускаються, render-distance обмежена | Це перевірка вхідних даних, не розрахунок технічних габаритів |
| Старий Unity export/пакування могло захопити локомотив або застарілі ресурси | Явно два бандли + receipt хешів; build перевіряє вміст і склад набору | Unity і Windows PowerShell ще не запускалися |

Виправлення координат — не новий power-flow solver: відстань усе ще
геометрична до джерела, а не сума опорів уздовж складного електричного графа.
Залишено характер авторської моделі навантаження/контакту. Навмисно не ввімкнено
закоментовані захисти roof_busbar, не додано алгоритму КЗ між пантографами,
не змінено ані двигун, ані регулятор, ані тарифи в основному ядрі.

## Перевірка залежностей 2WE3

У `WE6_pack.asset` оригіналу є `AdditionalDependencies: Catenary-DC`.
Тому «прибрати locomotive папки й залишити ту саму DLL» було б недостатньо:
2WE3CCL утратив би і очікуваний контролер, і залежність. Використано розділення:

- core UMM ID **DerailValleyCatenaryDC**, assembly **CatenaryDC**;
- необов'язковий окремий controller ID **Catenary-DC**, assembly
  **CatenaryDC.Legacy2WE3** — для сумісності з CCL;
- оригінальний **electric_sim** поруч не запускається.

Генератор читає exact snapshot, перевіряє 49 файлів, переносить реалізацію лише
в artifacts, прибирає її OCS setup і MOW-хук, перенаправляє обидва запити
пантографа, підключає/відключає simulate_all_units до core tick. Це локальний
тестовий засіб, не копія локомотива в основному src. Моделі не перепаковуються.

## Що НЕ перевірено або НЕ зроблено

- Компіляція C# net48, виконання C# test runner, Unity 2019.4.41f2 export,
  запуск PowerShell у Windows, завантаження та тяга у Derail Valley.
- Повна сумісність із невідомими новими версіями гри/автора/CCL, VR/multiplayer.
- Контактна конструкція авторських 31 файлів не виправлялася і не оголошується
  відповідною всім новим вимогам. Профіль лишається reference, а не final map.
- Довгі дроти: поліпшено пошук контакту, не переписано всі візуальні bounding
  volumes і culling. Перевірити появу дроту при телепортації/великій дистанції.
- Live Debug-редактор не є автоматичним валідатором механічних ниток, зигзага
  чи пантографної ізоляції; після електричних змін потрібен reload.
- Не побудовано HB–CS–CMS–вузол SM; не вигадані track IDs, координати або
  струмові ліміти нових підстанцій.

## Що фактично запускалося тут

`python tools/validate_project.py --upstream <розпакований оригінал>`:
перевірка даних, структури, asset GUID, source hashes, JSON/CSV references,
запропонованих source guards та підготовки optional adapter. Точні результати
в `audit/offline_validation.json` і `audit/offline_validation.log`.
Це не «N компіляційних тестів» і не свідоцтво відсутності всіх C# помилок.

`tests/CoreLogic` окремо підключає production-файли математики/стану/CSV.
19 тестів підготовлено для запуску користувачем; поки не позначено PASS.

## Порядок приймання

1. Offline checker → Unity export → core Release build.
2. Reference-layout smoke test дизелем, повторне завантаження світу.
3. Optional bridge build → Sandbox 2WE3 A/B → навантаження/відновлення джерел.
4. Debug authoring test окремо; перший production-коридор тільки після
   підтвердження стабільності нового ядра.
