# IMW–MF — фінальна прийнята версія

База патча: `full_circuit`, `27b08b55b0319603386e3b4240380ec602cb833f`.
Користувач прийняв Visual8 і завершив цю частину 15.11.2026.
Усі 12 JSON перенесено з `IMW-MF-Visual8.zip` побайтово, без зміни геометрії.

## Що входить

- Прийнята деелектрифікація IMW–CP та гілки до IMW зі збереженням FF–OR.
- IMW–MF — 1500 В; перехід одинарного/подвійного проводу на відтяжках між мостами.
- Пасажирський парк MF і військові I/O — тролей 750 В; військові S/L не електрифіковані.
- Промислові парки B/C — бокові рейки 1100 В із прийнятими стиками й центруванням.
- Усі прийняті правки анкерів, опор, нейтральної, знаків, переходів та південного заїзду.
- Виправлення трекера при повторному завантаженні збереження, описане нижче.

У бандлі тепер 54 розстановки, 14 982 об’єкти. Для чотирьох нових ресурсів
додано унікальні GUID; метадані восьми існуючих файлів збережено.
CP-станція й решта прийнятих ділянок поза 12 накладками незмінні.

## Застосування патча

У корені робочої копії проєкту:

```powershell
git apply --check IMW-MF-Final-27b08b5.patch
git apply IMW-MF-Final-27b08b5.patch
python tools/verify_network_release.py
python tools/validate_project.py
dotnet run --project tests/PlayerTracking -c Release
```

Для порівняння з прийнятим архівом, якщо він збережений:

```powershell
python tools/verify_network_release.py --imw-mf-accepted-zip IMW-MF-Visual8.zip
```

## Збирання й оновлення

1. У Unity **2019.4.41f2** відкрий `unity_project` та виконай **Catenary → Export OCS**.
2. Збери core через `BUILD.cmd` або `tools/Build.ps1`. Самої заміни JSON недостатньо
   для виправлення помилки: потрібен новий `CatenaryDC.dll`.
3. Для парного релізу повторно збери 2WE3 Bridge проти нового core і запакуй
   реліз за [звичайною інструкцією](BUILD_UK.md). Код і моделі 2WE3 не змінені;
   збірка потрібна для відповідності записаного SHA нового core.
4. Закрий гру, встанови новий білд та перенеси наведені тестові накладки
   з `Scenery` встановленого мода у резервну папку **поза модом**:

```text
scenery_[cp]![imw].json
scenery_[ff]![imw].json
scenery_[imw]![mf].json
scenery_cp-imw[imw].json
scenery_cw-mf[cp].json
scenery_ff-imw[ff].json
scenery_imw-ff[imw].json
scenery_imw-mf[imw].json
scenery_imw.json
scenery_mf-industrial.json
scenery_mf-military.json
scenery_mf.json
```

Регістр імен не має значення. Усі ці файли вже вбудовані в новий бандл;
залишені накладки перекриватимуть його. `included_scenery` залишай `null`.

## Помилка при повторному завантаженні

У `OCS_ticker.Update` залишився авторський рядок
`PlayerManager.ActiveCamera?.transform`. Під час зміни сцени нативна камера
може бути вже знищена, але її C#-обгортка ще зберігається в `PlayerManager`.
Оператор `?.` перевіряє лише C# null, тому викликає `Component.get_transform`
на знищеному компоненті — саме цей шлях відповідає наданому стеку.
Перевірки `player_view is null` також не враховували час життя Unity-об’єкта.

Застосовано `== null` / `!= null`, які враховують знищений Unity-об’єкт.
Якщо камера відсутня, використовується живий `PlayerTransform`; якщо немає
обох, пропускається тільки цей кадр, а на наступному робиться нова спроба.
Трекер прив’язано до його світу, вимикається до відкладеного `Destroy`,
відписується від подій навіть після знищення host і не передає старий tick
новій сесії. Якщо обробник `SimulationStep` вивантажує світ, симуляція
підстанцій після нього не виконується.

Unity документує цю особливість:
[Object, Unity 2019.4](https://docs.unity3d.com/2019.4/Documentation/ScriptReference/Object.html).
Такий самий доступ до камери є в авторській версії `e0b78cb`. Проте за цим
стеком не можна встановити всі причини старої проблеми зі зникненням частини
карти: це окремий симптом, без її логів причинний зв’язок не підтверджений.

Геометрію прийняв користувач у грі. Нове виправлення коду пройшло тести з
імітацією часу життя Unity-об’єктів; повний net48-білд, Unity-експорт та
повторне завантаження в самій грі тут не виконані. Після локальної збірки
перевір: завантаження → вихід у меню → повторне завантаження того самого
збереження, потім іншого; мережа й карта мають з’являтися, а цей стек не
повинен повторюватися. Також перевір телепортацію та зміну камери.
